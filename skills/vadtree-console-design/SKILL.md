# VADTree 证据桌设计

把界面当成一册正在被批注的调查档案，而不是一个“AI 仪表盘”。视觉选择服务于三件事：**找到值得看的证据、理解分数为什么这样、知道结论有多可信**。

## 1. 何时使用

使用：
- 新增 / 重做 VADTree 控制台页面（Overview、Runs、Evidence、Pipeline、Archive）。
- 需要把分数、时间轴、HGTree 节点、caption、CoT 放进同一个阅读路径。
- 页面功能齐全但看起来像通用后台，需要建立有辨识度的层级。
- 需要真实截图评审和减法精修。

不使用：
- 只改 API、脚本、数据格式。
- 已有明确品牌规范且与本 skill 冲突（品牌优先）。
- 单纯修一个按钮的 hover 色。

## 2. 设计立场

1. **证据优先于装饰**：每个视觉元素都要帮助定位、比较或解释证据。不能回答“它帮用户做了什么”的元素删掉。
2. **时间是脊柱**：视频异常检测的第一坐标是时间。曲线、节点带、GT 区间必须共享同一条时间轴；不要把它们拆成互不相关的卡片。
3. **不确定性可见**：发布值、复现值、warning、缺失数据必须显式标注。不要用漂亮图表掩盖“没跑过”或“对不上”。
4. **编辑式层级**：一个页面只有一个主标题、一个主数字或一个主任务。用字号、留白和细线建立层级，不靠阴影和发光。
5. **颜色是批注，不是背景**：纸色承担大面积，墨色承担文字，朱红只给异常/行动，苔绿只给通过/正常，赭石只给 warning。
6. **少而准的动效**：页面进入、时间轴 hover、抽屉开合即可；尊重 prefers-reduced-motion。

## 3. 流程

### 3.1 探索（方向不明时）

- 先读真实数据与现有页面，明确用户、主任务、最重要的判断。
- 给出约 3 个在**构图、信息组织、字体、交互隐喻**上真正不同的方向，不是换色。
- 写一份可执行 brief：用户 / 主任务 / 目标感受 / 隐喻 / 构图 / 色彩字体 / 关键交互 / 避免 / 最小范围。
- 用户已指定方向就遵循；允许自主推进时选最符合用途的一项并说明假设。

### 3.2 定义（实现）

- 先做承载主任务的一个代表页（通常是 Evidence 或 Overview），再扩展。
- 用真实 JSON 数据，不用占位曲线；没有数据就显示 “—”。
- 先建立 token（颜色、字号、间距、线宽、状态），再写组件；禁止页面内散落魔法值。
- 图表用 SVG 自绘，保证坐标、单位、时间码、空状态可控；不要为了“看起来专业”引入重型图表库。

### 3.3 真实截图评审

1. 在真实运行环境启动服务，用 1440×900 与 390×844 截图；覆盖默认状态、选中节点、空/缺失状态。
2. 独立评审上下文只给截图、用户/任务说明、brief；不给代码、实现难度、历史解释或期望分数。
3. 每轮只改最影响效果的 1–3 个问题，再截图。最多两轮；不收敛就报告剩余缺口。
4. 截图无法证明的交互、性能、无障碍行为标注“未验证”。

### 3.4 交付

- 删除重复说明、装饰容器、竞争注意力的效果。
- 检查窄屏、焦点、对比度、长文本、空数据。
- 交付说明：选定方向、关键删减、验证证据、未验证部分。审美与功能验证分开报告。

## 4. 视觉系统

### 4.1 Token

| 名称 | 值 | 用途 |
| --- | --- | --- |
| paper | #F4EFE4 | 页面底色 |
| paper-deep | #EAE2D2 | 次级底、表头 |
| card | #FAF7EF | 档案卡 |
| ink | #191713 | 主文字 |
| ink-soft | #4F4A40 | 正文次级 |
| ink-faint | #847B6A | 说明、轴标签 |
| rule | #D8CEBA | 细分隔线 |
| rule-strong | #B9AC93 | 表头/重点线 |
| vermilion | #C63F22 | 异常、主行动 |
| vermilion-deep | #9E2F18 | hover/pressed |
| moss | #355647 | 通过、正常 |
| ochre | #B07A2A | warning、待确认 |
| blue-ink | #2E4F6B | 链接、次要数据 |

规则：
- 大面积只用 paper / paper-deep / card；ink 不超过画面 15%。
- 朱红面积不超过 5%；不要用朱红做大按钮背景填满整屏。
- 不用纯黑 #000、纯白 #FFF。
- 卡片圆角 2px；表格和图表容器 0；不要 12–24px 大圆角。
- 阴影最多 0 1px 0 rgba(25,23,19,.06)；禁止发光。

### 4.2 字体

- **Fraunces Variable**：页面标题、章节标题、巨大指标数字。字号大时启用 optical size，字重 400–600；数字可用 300–400 形成编辑感。
- **IBM Plex Sans**：正文、按钮、表单。400 / 500 / 600。
- **IBM Plex Mono**：时间码、ID、参数、坐标轴、标签。400 / 500；tabular-nums。
- **中文界面**：Fraunces / IBM Plex 只承担拉丁字母与数字；中文标题回退到 Noto Serif CJK SC，正文回退到 Noto Sans CJK SC。中文标题不要用合成斜体，强调只用朱红或字重，不改变字形。

字号建议：
- display 72–96 / 0.94；h1 48–60 / 1.0；h2 30–36 / 1.1；h3 20–22 / 1.25；body 15 / 1.65；small 13 / 1.5；micro 10.5 uppercase + letter-spacing .12em。
- 大数字用 Fraunces + font-variant-numeric: tabular-nums；不要用等宽字体做 hero number。

### 4.3 布局

- 左索引栏 240–260px；右边内容最大 1500px；桌面 gutter 32–40px。
- 页面顶部有上下文条：数据集 / 运行 / 状态；下面是 masthead。
- 主内容用 12 列网格；图表可跨 8 列，说明跨 4 列。
- 窄屏 < 960px：索引栏变顶部横条；证据页三栏改为单列，时间轴横向可滚动，inspector 在下方。
- 不用“卡片墙”作为默认布局；优先用通栏、细线、留白和表格式节奏。

### 4.4 质感

- 纸纹：固定定位的 SVG feTurbulence 噪点，opacity 0.025–0.04，pointer-events none；不要用大图。
- 分隔线：1px rule；重要区块用 2px ink 或 1px rule-strong。
- 选中：左侧 2px 朱红 + 底色 paper-deep；不要用蓝色系统高亮。
- 标签：矩形、微 uppercase、1px 边框；不要胶囊形泛滥。

## 5. 组件配方

### 5.1 索引栏 / Spine

- 顶部 wordmark：Fraunces 28–32px，VADTree；下方 micro 文案 “TRAINING-FREE / EXPLAINABLE”。
- 导航项：两位编号 + 名称 + 可选计数；默认 ink-soft，hover ink，active 左侧朱红短线 + ink。
- 底部：机器状态点 + “LOCAL CONSOLE” + 版本/日期。
- 移动端：wordmark + 横向可滚动导航；隐藏底部 meta。

### 5.2 Masthead

- 上面一行 micro：SECTION / DATASET / RUN。
- 主标题 Fraunces，一句话说明这个页面在回答什么问题；不要口号式空话。
- 右侧可放一枚“档案章”：dashed 1px、微旋转 -1.5deg、mono 小字，显示复现状态/日期。
- 标题与正文之间用 1px rule 或 32px 留白，不套卡片。

### 5.3 Metric Figure

- 标签 micro uppercase；数字 Fraunces 72–120px，tabular；单位/范围用小字。
- 数字下方一行 delta 或对比：“vs coarse +0.0198”，正负用朱红/苔绿，但不要只靠颜色，带 +/-。
- 右侧可放一个 0–1 的刻度尺，标出当前值与基线；刻度用 1px 短线。
- 不用圆环进度、仪表盘、发光数字。

### 5.4 Score Strip（视频条带）

- 每条代表一个视频：左侧 mono 视频名（截断 + title），右侧 AUC。
- 中间 SVG：x=时间归一化，y=分数；曲线 1.25px ink；异常区间用朱红 10–14% 填充；GT 用斜线 hatch；底部 2px 时间轴。
- hover 显示时间/分数；点击进入 Evidence。
- 条带高度 48–64px；不要缩略图、不要 3D、不要渐变填充。

### 5.5 Evidence Timeline

- 高度 240–320px；上方 coarse 节点带、下方 fine 节点带，共享时间轴。
- 节点带颜色按分数从 paper-deep 到 vermilion 的离散 5 档；选中节点 2px ink 外框 + 朱红端点。
- GT 区间：斜线 hatch + 顶部 “GT” micro 标签；不要用大面积红色块遮住曲线。
- 曲线 hover：垂直细线 + 时间/分数 tooltip；tooltip 用 card 底、1px rule、mono 数字。
- 轴：只保留 0、中点、结尾时间码；单位秒 / mm:ss；标签 10.5px mono。
- 空状态：显示“该运行没有逐帧分数”，不要画一条假平线。

### 5.6 Node Inspector

- 标题：coarse/fine + 时间段 + 分数；分数用 mono。
- 两块文本：CAPTION（模型看到什么）与 REASONING / CoT（模型怎么想）；micro 标签 + 1px rule。
- 长文本最大高度 + 滚动；超过阈值显示 “truncated” 与展开按钮。
- 不要把 CoT 做成聊天气泡；它是证据边注。

### 5.7 Run Ledger

- 表格式：序号、运行名、数据集、阶段、ROC、PR、配置、视频数、进入箭头。
- 行高 56–64px；hover paper-deep；选中左侧朱红线。
- 数字右对齐、tabular；空值 “—”；warning 用赭石小三角 + 文本，不只靠颜色。
- 筛选用文本按钮/分段控件，不用大圆角 pill 群。

### 5.8 Docket Stage（Pipeline）

- 纵向 7 步；左侧大号 mono 编号，右侧标题 + 状态 + 依赖 + 命令摘要。
- 状态：PASS 苔绿、WARN 赭石、BLOCKED ink-faint、RUNNING 朱红脉冲（仅 1 处，尊重 reduced motion）。
- blocked 步骤要写清楚缺什么（视频、权重、环境），不要只显示灰按钮。
- 运行按钮是次要行动；主行动是“查看证据/报告”。日志用 mono、可滚动、限高。

### 5.9 状态语言

- PASS / VERIFIED：苔绿点 + 文本。
- WARNING：赭石三角 + 具体差异（Δ 数值），不要只写“注意”。
- BLOCKED：ink-faint 方块 + 缺失项。
- FAIL：朱红 + 错误摘要 + 日志入口。
- 任何状态都必须有文本标签；颜色只是辅助。

## 6. 数据真实性

- 只渲染 API 返回的真实字段；前端不做“看起来合理”的插值。
- 缺失字段显示 “—”；数组为空显示空状态；不要 fallback 到随机/演示数据。
- 区分 published / reproduced：表头或脚注写清楚来源；warning 保留在报告和 UI。
- 开放词查询：0–100 是视觉语言模型的**自评**，必须显式标注“非校准概率”，不能与 VADTree 的 ROC/PR 直接比较；先给时间定位和证据帧，再给分数。
- 截断 CoT 要标注；不要把摘要冒充原文。
- 图表必须有单位/时间码；不能只有形状。

## 7. 无障碍与响应式

- 文本对比度 ≥ 4.5:1；ink-faint 只用于辅助信息，不用于正文。
- 所有交互可键盘到达；focus ring 用 2px ink + 2px offset，不用默认蓝。
- hover 信息必须有非 hover 的等价入口（点击选中）。
- prefers-reduced-motion: reduce 时关闭位移动画和脉冲。
- 390px 宽度下无横向溢出；表格可横向滚动但页面不滚。
- 触控目标 ≥ 40px；导航项高度 ≥ 44px。

## 8. 评审清单

截图逐项检查：
1. 第一眼能否说出“这是 VADTree 的证据台”，而不是通用后台？
2. 主标题 / 主数字 / 主任务是否只有一个焦点？
3. 时间轴、节点带、GT 是否共享坐标且可对齐？
4. 朱红是否只出现在异常/行动？是否过多？
5. 字体层级是否靠字号/留白，而不是靠卡片和阴影？
6. 数字是否 tabular、右对齐、带单位？
7. 空数据 / warning / blocked 是否清楚且不误导？
8. 长 CoT 是否可读、可滚动、有截断标识？
9. 窄屏是否仍能完成“选视频 → 看时间轴 → 读节点”的主路径？
10. 删除任意一个装饰元素，是否影响理解？若不影响，删掉。

## 9. 反模式

- 深色渐变 + 霓虹青紫 + 发光边框的“AI 监控大屏”。
- 玻璃拟态卡片、大面积 blur、无意义粒子背景。
- 每个指标一张圆角卡片，页面变成卡片墙。
- 只有图标没有文字的导航。
- 用红/绿 alone 表达状态。
- 伪造视频缩略图或 demo 数据。
- 把 CoT 渲染成聊天气泡或营销文案。
- 为了“高级感”降低对比度或缩小正文。
- 无限滚动 + 无坐标的装饰性曲线。

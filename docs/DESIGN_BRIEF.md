# VADTree Console — Design Brief

日期：2026-10-24 · 范围：本地 WebUI（只读数据 + 复现任务控制）
参考方法：[distinctive-ai-design](https://github.com/houxin0010/distinctive-ai-design)（探索 → 定义 → 交付）

## 1. 用户与主任务

- **用户**：在单机工作站上研究 / 复现 VADTree 的研究者或工程师。
- **主任务**：判断“哪个数据集 / 哪次运行 / 哪个视频 / 哪个时间片”值得看，并理解模型为什么给出这个异常分数。
- **次任务**：重跑可确定性复现的步骤（2/6/7），核对发布指标，检查产物与环境。
- **目标感受**：像在翻阅一册有批注的调查档案——克制、可追溯、每一笔都有出处；不是“又一个 AI 仪表盘”。

## 2. 三个方向

### A. Evidence Desk（选中）
暖纸色、墨色、朱红批注；编辑式衬线标题 + 技术等宽数字；时间轴是页面的脊柱；卡片像档案卡而不是玻璃面板。
- 隐喻：异常检测 = 证据整理；HGTree 节点 = 被标记的片段；CoT = 边注。
- 适合：解释性、长时间阅读、对比分数与文本。

### B. Signal Room
近黑底、荧光绿/琥珀、示波器网格；适合实时监控，但容易落入“AI 监控大屏”的模板感，且长文本阅读差。

### C. Field Guide
浅色植物标本册、手绘分类树、纸质标签；与“层级树”很贴合，但对异常事件的紧迫感表达不足，视频时间轴会显得柔弱。

选择 A：它同时支持“调查叙事”和“数据密度”，且与常见的深色渐变 AI 面板明显区分。

## 3. 可执行 Brief

- **核心视觉隐喻**：调查员的证据桌 / 案件卷宗。
- **构图**：左侧固定索引栏（spine），右侧编辑式内容栏；大标题与巨大指标数字形成锚点；数据条带与时间轴横向展开。
- **信息层级**：页面标题 → 当前数据集/运行上下文 → 核心指标 → 证据条带/类别 → 运行台账/复现状态。
- **色彩**：纸 #F4EFE4、墨 #191713、朱红 #C63F22（异常/行动）、苔绿 #355647（通过/正常）、赭石 #B07A2A（警告）、蓝墨 #2E4F6B（链接/次要数据）。
- **字体**：Fraunces（拉丁展示/数字）+ Noto Serif CJK SC（中文标题）、IBM Plex Sans + Noto Sans CJK SC（正文/控件）、IBM Plex Mono（时间码/ID/参数）。中文标题不用合成斜体。
- **关键交互**：点击视频条带进入证据页；点击节点在右侧阅读 caption/CoT；运行台账可筛选；Pipeline 页可发起复现任务并轮询日志。
- **避免**：霓虹渐变、玻璃拟态、无意义发光、圆角 16px 卡片堆叠、只有图标的导航、隐藏 warning、伪造缩略图。
- **第一版范围**：Overview / Runs / Evidence / Pipeline / Archive 五个页面；真实读取 794MB 结果；步骤 2/6/7 的沙箱复现；真实截图评审。

## 4. 页面骨架

~~~text
┌───────────┬──────────────────────────────────────────────┐
│ VADTree   │  index / dataset / run context      status  │
│ 01 Desk   ├──────────────────────────────────────────────┤
│ 02 Runs   │  masthead + metric figure                    │
│ 03 Evidence│  score atlases / category lollipops         │
│ 04 Pipeline│  run register / reproduction stamp          │
│ 05 Archive │                                              │
└───────────┴──────────────────────────────────────────────┘
~~~

## 5. 数据真实性规则

- 所有数字来自 result/ 的真实 JSON；没有数据就显示 “—”，不生成占位曲线。
- 发布版 / 复现版的差异必须显式标注（例如 XD 的 numpy tie-order warning）。
- CoT 原文截断时标注 “truncated”，不摘要成看似原文的短句。
- 不使用视频缩略图：本机没有视频，用分数条带和节点带承担视觉叙事。

## 6. 评审计划

1. 实现 Overview + Evidence 代表页。
2. 用 Playwright 在 1440×900 与 390×844 截真实运行图。
3. 按构图、层级、字体、色彩、数据可读性、窄屏六项自查/独立评审；每轮只改最影响效果的 1–3 个问题。
4. 截图与修改记录写入 docs/DESIGN_REVIEW.md。
